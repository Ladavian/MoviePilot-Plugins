# StrmFlow × MoviePilot V3

这是 StrmFlow 的 MoviePilot V3 配套插件，使用稳定 SDK、公开订阅 Oper 和公开 SubscribeChain。本插件支持 MoviePilot **V3**，版本 1.0.3。源码位于仓库根目录 `plugins.v3/strmflowbridge`，市场索引为根目录 `package.v3.json`。这是独立公开项目，StrmFlow 主程序继续保存在私有仓库中。仓库不包含任何用户的密钥、站点配置或媒体数据。

支持 StrmFlow v0.2.0 的联动协议 v1。插件版本与 StrmFlow 版本分别维护。

## 配置

1. 在 StrmFlow「上传与 STRM → 本地上传」建立自动上传任务，映射你的硬链接目录，启用外部通知。设置「外部来源目录」为 **MP 容器实际看到的整理后路径**，本地来源目录为 **StrmFlow 容器实际看到的对应路径**。
2. 在「发现与订阅 → 订阅设置 → MoviePilot 联动」启用，选择上述上传任务，保存后复制专用联动密钥。不使用后台管理员密码或 JWT。
3. 在 MP「插件市场设置」添加独立仓库 `https://github.com/Ladavian/MoviePilot-Plugins`，刷新市场后安装 **StrmFlow 联动**。这是公开插件源，不需要授权读取 StrmFlow 私有主仓库。后续版本在 MP 插件市场中正常更新。多个插件源按 MP 设置要求用逗号分隔。

   如需手工安装，可以下载本项目 Release 的 `moviepilot-plugins-v3.zip`。开发调试时也可使用 `PLUGIN_LOCAL_REPO_PATHS` 指向解压后的本目录。
4. 在 MP 插件中填写可访问的 StrmFlow 根地址和专用密钥，启用。填写根地址，例如 `http://strmflow:18766`，不要附加 `/api`。MP 不在同一个 Docker 网络时使用 NAS 的局域网地址及实际管理端口。
5. StrmFlow 的订阅转存位置沿用「发现与订阅」默认转存库；请先配置它和可用的资源来源。首次订阅镜像会立即排一次检查；后续检查使用 StrmFlow 的订阅计划。

## 功能开关

总开关及所有功能开关默认关闭。升级旧版时，会先暂停旧联动配置，保留地址、密钥和待发通知；主程序配置好后再逐项开启。

| 开关 | 作用 |
| --- | --- |
| 总开关 | 控制整个插件；关闭时不运行任何联动 |
| 上传通知 | 硬链接完成后通知主程序上传 |
| 订阅同步 | 将 MP 订阅新增、修改及主动取消同步给 StrmFlow |
| MP → StrmFlow | MP 成功入库后，让 StrmFlow 跳过相同资源 |
| StrmFlow → MP | 读取 StrmFlow 已入库资源，过滤 MP 后续重复下载 |
| 自动完成订阅 | 在上一项也开启时，更新 MP 进度并通过正常流程完成订阅 |

可以只开上传，或只开某一方向的去重。只读去重不会创建 StrmFlow 订阅；关闭自动完成时不改写 MP 进度。禁用功能的旧通知保留在队列中，不会被其他功能误消费。

## 工作方式（按对应开关执行）

- 初次连接及相关操作事件触发时读取 MP 订阅；每 30 分钟补偿一次，匹配 TMDB 的电影、剧集及季/集段范围。MP 主动新增、修改和取消订阅会触发合并通知；主程序有入库变化时唤醒插件对账，空闲等待不反复交换完整数据；不会覆盖原本手工建立的 StrmFlow 订阅范围。
- MP 只在 `TransferComplete` 且实际目标视频成功时，记录已入库事实并通知 StrmFlow 上传。下载源路径、失败整理、单纯的 `DownloadAdded` 都不能当作完成。
- 通知写入插件自有持久化队列；未确认的通知会在下一轮重试，重复通知幂等。单次处理至多 100 条通知。上传映射异常时保留路径通知重试，同时继续对账已入库事实；未绑定上传任务时可仅做订阅联动。无 TMDB 身份的成功硬链接文件仍可通知上传，不猜测其媒体身份。
- StrmFlow 读取真正有效的 STRM/115 台账，向 MP 返回自己已有的电影及季集。MP 下载选择前短时对账；完整电影/单集直接跳过，已知季集的剧集包用 `allowed_episodes` 限制缺少的集。
- MP 已入库事实单独存储，参与 StrmFlow 缺集计算，在转存前再检查，不伪装为本地 STRM。StrmFlow 获取的文件仍须进入本人 115、核验并正常整理生成 STRM 后才算已有。
- MP 的电影、整季/集段范围确实补齐后，通过公开 `SubscribeChain.finish_subscribe_or_not` 完成，让 MP 正常写入历史及发布完成事件。部分剧集只更新 `note`，不会结束整季。

## 边界与验证

- 自定义剧集组、非 TMDB 且没有辅助 TMDB 身份的条目、洗版订阅不自动镜像，避免跨编号体系错误去重。无法确定的季/集号不会猜测。
- 跨系统通知不能原子撤回已经开始的 PT 下载或网盘转存。完成通知到达后阻止后续重复获取；不删除正在运行的下载、做种任务或媒体文件。
- 没有文件名/元数据中明确集号、也没有已知季集清单的整季包，不做猜测性逐集限制。
- 当前已经通过纯协议、模拟 V3 宿主生命周期与完成语义，以及 Go 端认证、幂等、季集范围测试。尚未在真实 MP V3 宿主安装加载或真实 PT/115 账号上联调，不能将这些测试等同于线上验证。
- 官方参考：[V3 开发指南](https://github.com/jxxghp/MoviePilot-Plugins/blob/main/docs/Plugin_Development.md)、[V3 事件合同](https://github.com/jxxghp/MoviePilot/blob/v3/app/schemas/event.py)。

### v1.0.4 修复

- 识别 MoviePilot V3 官方 `themoviedb` 身份及旧版 tmdbid 字段。
- 高频订阅变更保留第一次通知的执行时间，不反复替换待执行任务。
- 面板展示最近成功通信、可同步订阅数及脱敏错误原因。
- 配合 StrmFlow v0.2.1，上传通知仅唤醒主程序已绑定的任务。未设置外部目录映射时无需让两个容器的挂载名称相同；设置了映射时继续严格校验边界。旧主程序不识别新信号时仍发送路径并保留失败通知，升级主程序后再重试。

### v1.0.5

订阅同步附带海报。成功入库事件缺少文件清单时，只唤醒 StrmFlow 已绑定任务扫描，避免因为不同 MP 载荷格式而静默丢通知；不生成猜测的媒体入库事实。新增保存后测试一次上传触发及入库事件/上传确认状态。实时监控与外部通知独立工作。

### v1.0.6

- 修正 MP V3 `media_info` / `meta_info` 资源上下文读取，补上电影、单集及剧集包缺集过滤。
- 最终下载前重新核对当前资源，包含不在订阅列表内的条目，避免使用刚过期的入库结果。
- 「查看数据」持久保留最近 100 条通信与去重结果，展示最近 30 条；包含失败原因、上传接收与实际下载拦截。
- 已经进入下载器的任务不会被强行删除；通信不可用时会记录失败，不能保证跨系统同时发生的操作完全没有竞争窗口。
